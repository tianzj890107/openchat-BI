### 2026-09-21 · X360 流程定义接口接入：Spec + 红测（本批未改生产实现）

新增 "行动 → 转督办" 接入 X360 流程定义接口的第一批交付物（只读客户端 + 转督办换真
的 Spec、红测与实现提示词），并核验出当前生产实现的 4 类缺陷：

- **Spec**：`docs/specs/x360-process-definition-integration.md`。定义两个只读 GET
  （按流程定义 ID / 按 KEY）、流程定义与活动两级 ID、`responsiblePerson` 责任人接入、
  缓存与失败冷却、鉴权头（文档未写 → 沿用本体客户端的 `X-App-Id` + 可选 `Bearer`）、
  降级真值表与 `X360_*` 配置表，并列出 6 项必须上游书面确认的阻塞项。
- **红测**：`tests/test_x360_process_definition_red.py`（35 条，离线 loopback，无凭据、
  无真实服务）。实测 **32 failed / 3 passed**：19 条因 `bi_agent.x360` 模块不存在、
  9 条因 `_resolve_task_alert_target` 不存在、3 条因端点响应缺少 `source` 等字段、
  1 条因上游实际收到活动 ID（`2081949636213985282`）而不是流程定义 ID
  （`2081949112647405570`）。3 条绿色用例是"关闭时不出网 / 不回显 token / 上游失败仍
  502"的护栏。
- **实现提示词**：`docs/specs/x360-process-definition-integration-implementation-prompt.md`。
- **核验结论**：`bpDefinitionId` 参数名是"流程定义 ID"，而当前生产发的是**活动** ID；
  14 条硬编码关键词里 `履约单`、`线索`、`项目`、`合同` 四个 ID 在接口文档的流程定义中
  查无实据（其中 `履约单` 在文档里是 `订单` 活动下的任务，不是活动）；转督办责任人
  始终取环境变量默认值 `400`，与流程定义无关。本轮只交付 Spec、红测和提示词，
  **未修改任何生产实现**。
- **口径决定**：按 API 文档实现——`bpDefinitionId` 默认取流程定义 ID，并提供
  `X360_BP_ID_LEVEL=activity` 一键回退（纯配置）。上游未书面确认前，生产保持现状配置。
