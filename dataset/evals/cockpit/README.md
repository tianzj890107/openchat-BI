# Cockpit 黄金评测集 v1

## 范围与边界

本体分析已有 analytics 黄金集；Cockpit 此前主要依赖单元测试，缺少可评审的业务输入、独立期望及逐项结果。本集补充 50 条人工业务判定的合成用例：10 推理、6 分类、4 文案、16 插槽投影、5 范围过滤、9 任务令选择与动作类型。期望不从被测函数生成。

用例由历史故障模式改写，未包含真实客户、手机号、认证、业务库副本。每条包含 ID、优先级、业务理由、输入与预期。`manifest.json` 校验指纹；修改用例须评审并更新 manifest，禁止为消除失败反向修改业务期望。

**这不是完整模型端到端质量分。** 当前测试生产交付校验、投影和范围过滤，不发模型请求，不验证真实 AP SQL、浏览器渲染、调度性能、人员解析或 Fuxi 下发。15 个插槽被覆盖，不等于 15 张卡片有完整业务数据；表格行级正确性仍需单独联调。

## 执行

```sh
python -m scripts.run_cockpit_eval --output /tmp/cockpit-eval.json
python -m pytest -q tests/test_cockpit_eval_dataset.py
```

需已安装项目 Python 依赖。运行不读 .env、不连接服务或数据库、不打开业务页面、不触发模型和预热。测试只使用内存；报告只写调用方指定位置。严格模式有任一失败返回 1，异常单列为 harnessError，不算业务通过。

JSON 报告列出每条 expected/actual；不只给总分。manifest 和用例可静态评审。2026-11-02 收口后，CI 的 `cockpit-eval-delivery-gate` 已改为失败即阻断（`allow_failure: false`），只对这套离线交付层评测负责，不修改现有 analytics 评测门禁。它仍**不能**替代模型端到端、真实 AP/PG、浏览器渲染、调度性能和 Fuxi 下发验收。

可用 `--baseline <file>` 显式比较已评审的失败 ID 集合，校验用例指纹并拒绝新增失败及运行器异常；仓库不自动生成或启用失败预算，禁止悄悄接受 P0。
