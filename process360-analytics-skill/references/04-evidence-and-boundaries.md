# 状态、证据与边界

## 状态

`Process360Query/Analyze/Draft` 统一返回：

| status | 含义 | 交付要求 |
| --- | --- | --- |
| `ok` | 完整结果 | 正常出结论 |
| `partial` | 部分对象或字段缺失 | 披露缺失范围，不补 0 |
| `blocked` | 口径/权限/数据缺口 | 说明阻断原因和缺口，不产出结论性判断 |
| `needs_clarification` | 场景或范围不唯一 | 向用户提 2-3 个明确选项 |
| `not_applicable` | 该场景不支持此能力 | 报告能力缺口，不伪造替代结果 |

## 授权

- 身份由服务端解析并注入，模型不可见也不可覆盖。
- `grantKind=none` 拒绝取数；`restricted` 必须至少指定一个客户/负责人/产品维度，
  与查询筛选取交集；`all` 才允许全量只读。
- 空授权列表不等于“不限制”。

## 证据

- `Process360Analyze.candidateCauses` 是候选原因，不是已确认根因。
- 证据哈希只能证明内容未变化；还需来源可信、对象/期间匹配、验证规则和反证检查，
  才能升级为已验证原因。
- 缺证据时只能提出核查任务，不得写成已确认根因或已观察风险。

## 数据来源

- 只认 `dataSource=process360-postgres` 与 `sourceConnection=pg:<host>/ywln#ywln_crm`。
- 连接串、SQL、`meta_*` 表名不进入 Fuxi 对话或 HTML。
- 返回其他数据源时停止并报告链路异常。

## 禁止

- 不执行发运、签单、调价等业务写操作。
- 不因取数 blocked 改用通用采购域、演示数据或本地脚本补数。
- 不删除、覆盖或迁移历史会话和用户数据。
- 不伪造发运/签单/排产等业务执行结果，不把创建待办表述为业务操作成功。
