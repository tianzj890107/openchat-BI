# 图库检索规则 · 上下文提取阶段 & 根因分析阶段

> 适用范围:**检索模式 = 图库检索**。
> 实现位置:`bi_agent/ontology/retriever.py`(`GraphRetriever`)、`bi_agent/tools/graph_tools.py`(`GraphContext` / `GraphExpand`)、`bi_agent/web/app.py`(`GRAPH_MODE_SOP`)。
> 核心原则:**大模型负责语义匹配,检索器负责确定性遍历**;所有遍历都跑在内存中的 `OntologyStore`(图的源数据),始终与已加载本体源一致,不解析持久化的 `.graphml`。

---

## 一、上下文提取阶段(第 3 步 · 上下文准备)

对应工具 **`GraphContext`** → `GraphRetriever.context_bundle()`。
目标:由一个锚点一次性拉取其下挂的全部本体行信息,**剪枝去重**后作为回答问题的背景上下文。

### 1.1 锚点定位(`resolve_anchor`)

把**原始问题**里的业务名词分别与「业务对象库」和「指标库」匹配,锚点类型 ∈ `{业务对象, 指标}`。匹配优先级:

1. 显式编码(`BOxxxx` / `Mxxxx`)直接命中;
2. 名称 / 别名 / 英文名**精确**匹配;
3. 名称 / 别名**部分**匹配(子串)。

**歧义处理(必须保留用户确认能力)**:

- 若 `query` 命中**多个候选锚点**且无法从问句唯一确定 → **调用 `AskUser` 让用户确认**,再用其选定项的 `anchor` 编码重新调用 `GraphContext`;
- 候选唯一或问句已明示时,直接选定,不打扰用户;
- 一个都没命中 → 提示改用 `ListBusinessObjects` 浏览后再指定 `anchor`。

### 1.2 业务对象锚点 → 下钻子树(`_bo_subtree`)

返回:

- **业务对象**本行;
- 其下**全部逻辑实体**,每个逻辑实体附:
  - 该实体的**全部业务属性**;
  - **ER 关系(收口规则)**:**仅当该 ER 关系的源逻辑实体与目标逻辑实体都在当前业务对象锚点下时,才收录**。跨业务对象的 ER 关系在本阶段**主动排除**,留到根因分析阶段由 `GraphExpand` 扩散获取;
- 该**业务对象下挂的全部指标**。

### 1.3 指标锚点 → 下钻子树(`_metric_subtree`)

返回:

- **指标**本行;
- 该指标的**可下钻维度**(维度行);
- **指标维度矩阵**(该指标的适用维度清单);
- **上挂其所属业务对象作为新锚点**,并对该业务对象执行 1.2 的全部下钻(逻辑实体 / 业务属性 / 业务对象内部 ER 关系 / 业务对象下指标)。

**指标下钻维度的确认**:若锚点指标的可下钻维度多于 1 个、问句又没点明下钻方向,且问题属于 L2 及以上分析 → **调用 `AskUser` 让用户选择主下钻维度**(可多选);问句已点明("按事业部""按季度")或仅单一维度则直接采用。

### 1.4 剪枝去重

整个 bundle 共享一个 `seen` 集合,业务对象 / 逻辑实体 / 业务属性 / 关系 / 指标 / 维度均按编码去重,**同一行信息只出现一次**。返回的即"已剪枝去重的背景上下文",直接作为后续规划与 SQL 的依据,无需再逐个 `EntityDescribe` / `MetricLookup`(仅在核对单个元素细节时才补用)。

## 二、根因分析阶段(第 5 步 · 深度分析增强 · 图库扩散探索)

对应工具 **`GraphExpand`** → `GraphRetriever.expand()`。

**触发条件(双重约束,做减法)**:

- 仅 **L3–L5**(含根因 / 决策 / 执行)使用;
- **且**仅当 `GraphContext` 给到的上下文不足以支撑根因 / 决策时才调用;够用就不扩散。

**入参**:业务对象编码 `BOxxxx`;若传指标编码会**自动定位到其所属业务对象**作为扩散起点。

从锚点业务对象出发,**两条路径并行**扩散到相关业务对象,再下钻其子树:

### 2.1 活动流扩散

1. 锚点业务对象下的**活动** → 各活动**所属流程**(取**整条流程行信息**,含流程内全部活动);
2. **活动上下游**(`活动流` 的 源节点→目标节点 流转,next / prev 邻接);
3. 上述邻接活动**操作的业务对象**(排除锚点自身)即为相关业务对象。

### 2.2 ER 关系扩散

- 遍历锚点业务对象下**逻辑实体的 ER 关系**;
- 找到落在**其他业务对象**下的对端逻辑实体;
- 把这些对端逻辑实体所属的业务对象加为相关业务对象。
- 输出会列出跨业务对象的 ER 桥接(如 `采购订单发运行 --被验收--> 采购验收单行 → 业务对象 [BO0006] 采购验收单`)。

> 这正是与上下文提取阶段互补的设计:**业务对象内部的 ER 关系在第 3 步即可见;跨业务对象的 ER 关系只在根因分析阶段、且大模型主动调用 `GraphExpand` 时才扩散获取。**

### 2.3 新增锚点下钻

- 把 2.1 + 2.2 发现的相关业务对象**去重**后作为新锚点;
- 对每个新锚点执行 1.2 的下钻(`_bo_subtree`:逻辑实体 / 业务属性 / 内部 ER 关系 / 业务对象下指标),与锚点自身共享去重集合;
- 由此补足跨域上下文。

## 三、两阶段对照

| 维度 | 上下文提取阶段(GraphContext) | 根因分析阶段(GraphExpand) |
|---|---|---|
| 何时触发 | 每次提问的第 3 步,必做 | 仅 L3–L5 且上下文不足时,按需 |
| 起点 | 业务对象 / 指标锚点 | 业务对象锚点(指标自动上挂到 BO) |
| 业务对象内部 ER | 收录(源、目标均在锚点下) | —— |
| 跨业务对象 ER | **不收录** | **沿 ER 扩散到相邻业务对象** |
| 活动 / 流程 | 不主动展开活动流 | 沿活动→流程、活动上下游扩散 |
| 产出 | 单锚点剪枝子树 | 多个上下游业务对象的子树 |
| 去重 | 单 bundle 内 `seen` | 跨所有新锚点共享 `seen` |
