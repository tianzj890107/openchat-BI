# Process360 客户本体 Excel 更新（2026-11-03）

## 输入与范围

本次依据用户本地原始《亿纬锂能_流程360本体元模型_V3.1_新增数据表联动版.xlsx》和《部署包.zip》中的建表、兼容视图及外键声明，生成独立客户版本体。原文件不覆盖，原数据库部署 ZIP 不修改，不连接客户数据库、不执行 SQL、不部署、不切换服务配置。

生成器：`scripts/build_customer_process360_ontology.py`。原始客户文件和生成的交付物不提交 Git；代码仓库只保存生成器、合成 fixture 测试及交付说明。

```bash
.venv/bin/python scripts/build_customer_process360_ontology.py \
  --source '<原始本体.xlsx>' \
  --package '<数据库部署包.zip>' \
  --output '<新的客户本体交付目录>'
```

## Excel 与运行时交付

- 逻辑实体映射、属性映射改为 DDL 声明的 `ded_public` 物理表与真实字段，保留原映射便于追溯。
- 兼容视图内 `NULL::<类型>` 占位和未定义字段不登记为实际来源：来源字段留空，标记 blocked。缺少物理表的实体来源也留空。
- 属性表附加治理后的物理类型、非空和主键信息，不擅自修改逻辑属性类型、业务公式、阈值、审批与原执行许可。
- 实体关系标注对应 DDL 外键；仅表示 DDL 声明，不表示客户库的 `VALIDATE` 已通过。保留未匹配关系供核对。
- 新增客户部署说明、33 张物理表、2545 个物理字段、38 个外键、适配缺口、206 个指标结构影响工作表。审计表与尚未纳入原本体的项目表明确列出，不擅自新增业务对象和指标。
- 配套生成 `catalog.json`，保留原 18 个 SOP；本地 Excel 与 JSON 的哈希在 manifest 中关联。保留未修改工作表在原文件中的公式缓存，避免 openpyxl 保存后缓存丢失影响运行时。
- 生成 `manifest.json`、`适配核对报告.json`、`README.md`；目录已存在时拒绝覆盖，不能误覆盖用户旧交付物。

Process360 运行时读取 JSON，不直接热加载 Excel。后续授权部署时，须一起交付 Excel 与对应 JSON，再将 `PROCESS360_CATALOG_PATH` 指向客户 catalog；原默认 catalog 不修改。数据库名称、schema、认证、只读权限仍属于运行配置，不写入本体，更不写入密码。
