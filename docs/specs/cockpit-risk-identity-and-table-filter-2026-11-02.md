# 风险统计及表格局部筛选修复

## 风险事项

旧统计按指标编码数组去重。同一目标缺口引用不同指标组合会重复，自动生成的文字指标标签与模型引用的指标编码也不能合并。同一组指标上的不同异常则可能被误合并。另有按插槽节点筛选领域的问题：商机卡中归为出货领域的风险被漏掉。

新增服务端业务事项识别规则，覆盖出货目标缺口、客户发货目标缺口、商机目标覆盖不足、未签单商机零金额、报价逾期、投标周期、投标逾期、丢标、订单取消变更、PACK 商机未进入投标。已有缓存的节点交付投影和顶栏统计均使用同一识别函数，不需要重跑模型、SQL或清空历史分析。

未知事项保留领域和规范化标题作为标识，避免仅因为引用同一指标而被合并。这不是通用语义相似度模型；新增业务风险需要补充明确归并规则和回归用例。汇总返回 findings 清单，每项包含 riskKey、领域、标题、说明及来源插槽／分析 ID／证据 ID。count 等于清单长度；不同角色的证据与发布版本仍按原机制隔离。

## 局部筛选

交付 table 组件调用 runtime.setFilterConditions 时，宿主此前把它与日期等全局控件一起计入 uiScope，继而执行 clearScope、重建 runtime 和全部组件。现在从实际交付配置收集 table/dataTable/datatable 的组件 ID；这些组件的筛选仍交给原 SDK 执行和重放，但不改变宿主全局 uiScope、初始化基线或待处理全局筛选。全局日期、年度／月度控件维持原行为。

该修改针对宿主引起的整页重建，不处理上游表格重复客户、人员串联、多指标口径对不上等 AP 数据质量问题，也不修改厂家组件、指标和模板。

## 验证范围

新增 Python 风险识别测试及 Node 局部筛选、重置、重放测试，覆盖同风险不同指标组合、自动标签与编码同义、跨节点领域、同指标不同事项、节点与综合卡的订单变更同义。运行 Cockpit Python 和相关前端回归；真实 AP 历史响应仅作本地只读对照，不重新触发 AP／模型。本轮不部署。

浏览器回归脚本：`tests/cockpit_table_filter_browser.mjs`，配合隔离 fixture `tests/cockpit_performance_preview.py` 和本地 Chrome CDP 运行；不连接真实 AP 或模型。客户等级 1／2／重置均确认 DOM 与 runtime 实例保持。
