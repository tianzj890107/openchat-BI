# Cockpit 两轮交付与卡片质量验证（2026-11-10）

## 交付范围

固定卡片最多两次模型请求：第一次提交完整结构化卡片；正常草稿被拒绝时，第二次仅 JSON Patch 修补具体字段，服务端保留其余字段并完整重验。截断为空的草稿在第二次使用完整交付 schema 重交。没有通过则保留上次已发布结果，不能把普通文字当成成功卡片。普通分析员对话不受影响。

主风险卡原先只显示 summary，遗漏 findings 列表，导致多条风险看起来只有一条；现在逐项显示最多四条。原因、建议同样最多四条；相同风险去重。确定性的展示顺序优先履约逾期、目标偏差与持续恶化，再考虑转化和过程异常；这不是经过业务批准的量化风险评分，不跨单位比较影响金额。原因仍区分待验证机制与有记录支持的机制，核查动作可直接引用风险证据，不能为了挂建议编造原因。

## DeepSeek 实测方法

- 实际模型：团队网关的 `direct-deepseek-v4-flash`，不是 mock 模型。
- 输入为相同的已发布冻结记录子集：商机 24 行/5 个可重放查询，订单 21 行/9 个查询，发货 24 行/13 个查询。
- 只读获取历史证据，随后在临时测试存储中重放；不重算生产任务、不调用 AP/SQL、不下发任务、不改服务器。
- 每节点重复三次。以下为分阶段最后一组回归；商机、发货先完成回归，订单在最后修复输出余量和空草稿兼容后重新测试。不能把这些视为同一生产流量上的统计成功率。

| 节点 | 通过/测试 | 一次/两次模型请求 | 投影后风险 / 原因 / 建议数 | 耗时范围 |
|---|---|---|---|---|
| 商机 | 3/3 | 3 / 0 | 3 / 2–3 / 3 | 27.0–51.8 秒 |
| 订单 | 3/3 | 2 / 1 | 3 / 2–3 / 4 | 28.7–46.4 秒 |
| 发货 | 3/3 | 3 / 0 | 2 / 2–3 / 3–4 | 42.9–52.1 秒 |

所有通过样本均为 `limited`：表示有证据范围限制的合法卡片，不能解释为完整业务验收，也不能把假设称为已证实根因。该输入没有包含全部 AP 查询结果及全部事实，因此表中条数不是完整线上数据应有的风险总数。证据只支持一两项时，不能为了凑三四项加入正常在途、单纯缺数或同一风险的不同说法。

## 测试中实际发现并修复的失败

探索版本出现过 9 次中 1 次失败、3 次中 1 次失败；未把这些失败抹去或算作成功。主要问题及最终处理：

1. 通用对话的追问、表格与行动文案修复占用轮数：固定卡片使用专用交付路径，关闭 AskUser 和额外叙述修复。
2. 全量重写修好一个字段却漏掉其他字段：正常草稿改为局部修补。
3. 字段错误先返回，语义错误下一轮才出现：第一次反馈同时列出可发现的字段与业务校验问题。
4. 安全的独立单位观察、“不比较”“未相加”被误判：修正否定与独立观察识别；保留真实跨单位推断、集合合计、取消金额等于损失等反例测试。
5. 机制描述提及客户等级、产品团队就被当成结构原因：标题仍先过滤事实/结构/缺数，明确声明的机制假设不因核查范围出现维度名称而改变分类，不升级为已证实原因。
6. 全局报错无法定位修补位置：附具体字段路径及原句；支持标准 JSON Patch 数组追加。
7. DeepSeek 网关仍返回推理内容，8192 token 上限可能截断工具参数：任务局部提高到 16384 上限，保留低推理强度请求；空草稿第二轮按完整 schema 重交。这个值是余量，不要求模型输出这么多 token。

## HTML 证据与自动验证

完整证据 HTML 从保存的查询行生成最多三个趋势/分布图，保持单查询、单指标、原始单位与溯源，保留零值；维度缺失或类别重复无法确认粒度时不造图。没有新增模型/AP 请求。本地 ECharts 内联，缺资源时保留证据表，不请求 CDN。

自动回归：481 项 Python 测试、27 项 subtests、107 项 Node 测试通过；`git diff --check` 通过。

Chrome 离线检查：实际渲染一个图表 canvas、无脚本错误；主风险面板三项 findings 实际渲染三项、无脚本错误。另有四类条目通过校验与主卡投影后各保留四项的回归用例。

实测工具：`scripts/run_cockpit_model_canary.py`。需要显式 `--allow-model`，可使用 `--source-file` 重放同一批数据；原始报告与业务数据不提交。小样本不能保证生产永不失败，部署后仍应观察交付失败率、错误类型及分位耗时。

本轮仅提交与推送源码，不部署、不替换 tar、不合并 master。
