# 储小策智能助手迁移到完整 AgentKit 工作台

2026-11-27 修订 · 完整工作台接入待实施。目标分支为 `feature/chuxiaoce-agentkit-ui`，起点为 GitHub `feature/20251031-20261126@49f8988d19fdc6a3fa50fda10ba8191d6ace89f6`。界面和交互基线为分析 Agent 的 `/workbench-agentkit`，对应 `fd2450fec1a48258566c862b36a9bcc48500c3aa`。产品名称沿用「储小策智能助手」。[360 分析说明](../analysis360.md) · [驾驶舱视觉原型](../../V6.1-总裁驾驶舱-视觉%288%29.html)

## 1. 根因与迁移目标

原规格把 `App.jsx` 写成组合参考，并允许简版 Composer、独立嵌入布局和隐藏侧栏。首版据此新建 `EmbedApp`，独立维护会话列表、输入和布局，只装配了对话、SOP 和看板等部分组件。后续修复让默认页能提问、看结果和恢复基础历史，页面仍由独立的 `.ak-embed` 树渲染。底部导航、共享会话列表、分隔条、完整 Composer、交接提示、本体图和设置面板因此没有装配，部分功能也缺少接入 360 数据的动作。[当前嵌入页面](../../frontend/agentkit/embed.jsx) · [完整工作台组件树](../../frontend/agentkit/App.jsx)

**用户从驾驶舱点开助手，默认看到分析 Agent 的完整工作台体验。** 桌面首屏同时提供品牌与会话侧栏、对话与贴底输入框、对话看板，并共享响应式导航、栏宽拖动、主题和交互。只有储小策品牌、欢迎语、驾驶舱的返回/收起操作、360 数据与服务端授予的控件权限有专属配置。仅挂载部分子组件、按需切成互斥的对话和看板页面，均达不到默认桌面布局的验收条件。

| 入口 | 接入目标 |
| --- | --- |
| 驾驶舱助手 | 复用现有 `GET {APP_ROOT_PATH}/workbench?a360=assistant&view=board`。以 `a360` 的精确值选择储小策模式，`view=chat` 继续支持回到驾驶舱主页。 |
| 回退 | 沿用 `WORKBENCH_ASSISTANT_UI=legacy` 在同一 URL 返回旧助手，验证回退后可打开既有会话。 |
| 其余页面 | 普通 `/workbench`、已有的 `/workbench?a360=<编号>` 与交接 API 沿用原合同。本分支无需新增助手页面路由，`/workbench-agentkit` 用作体验对照。 |

入口红测覆盖直连、`APP_ROOT_PATH`、网关剥前缀、刷新和非法助手参数。页面资源沿用独立版本化构建，避免覆盖其他页面资源。[工作台路由与回退](../../bi_agent/web/app.py#L1400) · [驾驶舱宿主](../../bi_agent/web/static/cockpit/assistant.js) · [客户入口](../../bi_agent/web/customer.py)

### 2.1 客户入口控件

权限开关按服务端提供的能力生效。在客户入口，采用「信息可看，未授权动作隐藏」的默认选择。若之后开放某项能力，对应共享组件即可按权限恢复原交互。

| 组件位置 | 客户入口默认体验 | 请求边界 |
| --- | --- | --- |
| 底部「本体库 / 数据源」 | 在同一入口打开只读详情，展示已配置的 360 本体和数据源名称或可用状态。隐藏切换、编辑与保存。 | 只读限定的 360 元数据。加载页面、打开详情和提交问题均不请求通用数据源目录和写接口。 |
| Composer 的模型选择 | 保留同位置短模型名和全名提示，显示真实团队模型或「团队模型」回退标签。无修改权限时不展示切模型、参数、密钥等操作，可打开只读信息。 | 从受允许的有效运行配置或限定的 360 元数据取名称。禁止为了渲染控件自动调用通用模型配置接口。 |
| Composer 的报表与附件 | 客户入口当前不开放上传，隐藏报表附件的「＋」、上传和生成控件；历史中的授权产物和附件引用照常回看。 | 挂载及任何 360 交互均不自动探测或调用通用报表接口。 |
| 其他导航与行动 | 保留会话列表、三视图导航、SOP、工具、看板、历史、授权证据与子图。 | 只支持 360 客户权限允许的动作。真实权限错误在动作附近提示，页面首屏应无预期的 403/404 请求。 |

## 3. 技术实现

### 3.1 共用完整工作台

以当前分支已经引入的 `frontend/agentkit/App.jsx` 为基础，抽出同一完整工作台组件树，由通用页面与储小策入口共同调用，或直接让 `App` 接收模式与服务适配。共享 `SessionList`、导航、`Thread`、`SopBar`、`Composer`、`Board`、`PanelDivider` 及按业务状态挂载的 `HandoffBanner`、`OntologyGraph` 和设置面板。储小策入口只做 React 挂载以及注入品牌、欢迎语、360 transport、能力和宿主动作。默认桌面采纳同一布局、比例和主题规则。停止使用独立 `.ak-embed` 和第二套输入框或会话列表。

沿用 React 18 与 `@assistant-ui/react@0.14.14` 及现有锁文件。保留 AgentKit 固定来源 `b8df86dfa3c30de6676cd1d768cda504bf3c3338`。若需补文件，按来源清单从固定提交取用并校验。沿用 `frontend/vite.agentkit-embed.config.js`，生成独立 JS/CSS，复核运行时资源、容器产物和缓存基址。[AgentKit 来源](../../frontend/agentkit/UPSTREAM.md) · [嵌入构建入口](../../frontend/vite.agentkit-embed.config.js)

### 3.2 视图和宿主协议

保留宿主的 `closed/home/board` 与同源 iframe。宿主的 `board` 状态表示打开完整工作台，宽屏对话和结果并列。宿主的 `home` 状态只改变可用宽度和看板归属，左侧约 420px 可使用共用窄屏导航访问会话与对话。储小策看板可用时由「显示对话看板」扩回完整工作台。移动端采用共享视图切换。看板跳转回问题是工作台内动作，保持宿主工作台状态。

继续支持 `ready` 握手、宿主 `view: chat|board` 和子页 `request: board|home|close`，校验 origin、来源窗口、消息类型与枚举值。切换过程中保留当前轮、草稿、待澄清、滚动锚点和宽度偏好，容器尺寸变化后重排图表。[现有消息合同](../../bi_agent/web/static/cockpit/assistant.js)

### 3.3 360 模式服务适配

| 服务 | 接入方式 |
| --- | --- |
| 聊天与澄清 | `POST /api/analysis360/chat` 携带 `analysis360_direct: true` 和当前 `session_id`。`POST /api/analysis360/choice` 使用同一会话及原选项。两类请求都进入同一 SSE reducer，回合和请求 ID 按现有合同关联。 |
| 360 历史 | 将共用会话列表和历史动作接到已有 `GET /api/analysis360/history`、`GET /api/analysis360/history/{session_id}` 与 `POST /api/analysis360/history`。历史可回看与服务端能够续作分开判断。 |
| 交接与图表 | 实际交接进入原 `/api/analysis360/handoff` 合同。原生 360 证据的 `columns/rows/evidenceId` 转为共用看板表格，保留来源和预览范围。已有结构化图表和产物按原格式渲染，缺少证据时显示正常空态。 |
| 本体子图 | 使用已授权的 `G360GetSubgraph` 结果或 360 范围内已授权的读取动作，将图数据映射到共享图组件。扩散仅在相应 360 合同可用时启用。 |
| 模型及数据源 | 由服务端发出的有效配置和能力决定只读信息与控件可用性。请求由 360 模式适配统一约束，避免共享组件挂载时调用通用配置接口。 |

状态由共享 reducer 管理，接口选择集中在 transport 中。新建、打开历史和切换模式时隔离旧流。已有 360 历史接口当前提供快照存取，交付前须验证服务端的归属与授权，列表、读取、保存均按当前访问范围拒绝跨范围记录。恢复服务器已失效的 360 run 或待澄清时，保留可读取内容并说明续作状态。使用原存储卷和既有标识，历史记录就地读取。[360 接口](../../bi_agent/web/app.py#L3252) · [证据工具](../../bi_agent/analysis360/tools.py)

## 4. 红测与准出

| 顺序 | 先写会失败的用户路径 | 通过标准 |
| --- | --- | --- |
| 1. 默认页体验对照 | 用真实浏览器从驾驶舱右下角打开助手，在任何点击之前检查品牌、侧栏、新建、历史、底部导航、对话、Composer、看板、分隔条；与同宽度的分析工作台对照。 | 可见节点、顺序、尺寸和操作明确对应。DOM 契约验证两种模式挂载同一共享组件树。只看到标题、输入框或任一看板节点的冒烟测试不能通过此项。 |
| 2. 布局和用户操作 | 桌面拖动两条分隔条并用键盘调整。窄屏可切会话、对话、看板。返回主页、恢复看板、收起再打开。 | 默认直接提问，滚动时输入贴底。切换保留 iframe、筛选、草稿、问题位置和流；正常图表可重排。 |
| 3. 360 功能 | 用同一组脱敏 360 响应验证自由提问、流、六步 SOP、澄清失败重试、看板证据、真实交接和授权子图。 | 业务模块在适用场景实际挂载且可操作。自由提问、无结果及无交接有明确空态。验证只有 360 专用聊天、澄清和历史端点被使用。 |
| 4. 客户权限与回退 | 检查初次打开、设置点击、历史切换的网络记录。用不同权限夹具验证只读或隐藏，模拟无权限和服务异常。用同一测试卷验证两种 UI。 | 首屏及正常操作无通用 API 的 403/404 或功能探测。跨范围历史请求受阻。已有 360 会话回看正常，同一 URL 可切回旧页。 |
