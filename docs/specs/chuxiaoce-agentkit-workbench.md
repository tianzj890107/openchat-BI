# 储小策智能助手迁移到 AgentKit 工作台

2026-11-27 · 待实施规格。目标分支为 `feature/chuxiaoce-agentkit-ui`，起点为 GitHub `feature/20251031-20261126@49f8988d19fdc6a3fa50fda10ba8191d6ace89f6`。视觉和交互参考分析 Agent 已交付的 `/workbench-agentkit`，以分析仓 `fd2450fec1a48258566c862b36a9bcc48500c3aa` 中的前端为取样基线。产品名称沿用驾驶舱中的「储小策智能助手」。[360 分析说明](../analysis360.md) · [本分支驾驶舱视觉原型](../../V6.1-总裁驾驶舱-视觉%288%29.html)

## 1. 迁移目标和入口

驾驶舱右下角入口继续打开储小策。对话、SOP、工具调用、输入框和对话看板使用现有 AgentKit 工作台的组件、样式和交互。助手在驾驶舱里采用嵌入布局。驾驶舱负责主页看板与停靠状态，储小策负责 360 对话与当前对话看板。智能助手依旧使用原有的 360 全局本体、团队模型、只读数据源和六步 SOP。现有驾驶舱页面、筛选和卡片计算以原分支为准。

| 入口 | 实施目标 |
| --- | --- |
| 新版 | `GET {APP_ROOT_PATH}/workbench-agentkit?a360=assistant&view=board`。在客户入口只允许这一页面的助手模式，`view=chat` 用于主页看板状态。 |
| 旧链接与回退 | `/workbench?a360=assistant` 保留旧页面，预览验收通过后驾驶舱入口改指新版。保留一个服务端可选的前端版本开关，回退只切 iframe 地址。 |
| 其他入口 | 普通 `/workbench`、已存在的 `/workbench?a360=<编号>` 和交接 API 按原合同服务。保留深度分析链接的行为及过期反馈。这个 GitHub 基线的风险行已取消「深度分析」按钮，新助手也从右下角直达。 |

客户交付入口在精确路由上校验 GET、助手模式及前缀，后端也校验自己的 360 接口。测试覆盖无前缀、有 `APP_ROOT_PATH`、网关剥前缀、带 query/刷新，以及静态资源与 Cookie。新版与旧版同时随容器产物提供，各自使用独立资源目录和带版本的资源 URL。[驾驶舱宿主](../../bi_agent/web/static/cockpit/assistant.js) · [旧页引导](../../bi_agent/web/static/analysis360-handoff.mjs) · [客户入口边界](../../bi_agent/web/customer.py)

## 3. 实现方式

### 3.1 按文件引入现有 AgentKit 实现

该 GitHub 基线没有 `frontend/agentkit/`。以固定提交提取已验证的 UI 源码，保留来源记录。先用 `git diff`、`git show fd2450f:<path>` 检视文件差异和组件依赖，再按清单从固定提交引入。首批包括 `Thread`、`Composer`、`SopBar`、`Board`、主题、Markdown/ToolGroup、状态 reducer、消息适配器及必要的历史/结果投影。通用 `App.jsx` 作为组合参考，用嵌入模式装配可复用组件，显式注入 transport、能力和宿主动作。根据组件依赖保留既有 React 18 与 `@assistant-ui/react@0.14.14` 的兼容组合，核对 lockfile 后构建。

复用现有 `frontend/vite.agentkit.config.js` 的独立构建方式，输出到 `static/vendor/agentkit/`。引入 `UPSTREAM.md` 和对应组件的上游快照。原始仓库 `git@gitlab.boulderaitech.com:ai-team/spzn-agentkit.git` 的基线为 `b8df86dfa3c30de6676cd1d768cda504bf3c3338`，需要补充文件或升级时才用固定提交归档及哈希校验，构建只读取已入仓代码和锁定依赖。控制分支增量，避免把通用工作台的默认入口切换、数据源发现、版本、部署记录或业务后端随组件引入。

### 3.2 驾驶舱宿主和助手视图

沿用 `cockpit/assistant.js` 的 `closed/home/board` 状态与同源 iframe。打开首次读取 URL 的 `view`，子页挂载后用 `ready` 握手重收最新状态。宿主发 `view: chat|board`，子页发 `request: board|home|close`，每个接收端校验 `event.origin`、`event.source`、`source=cockpit-assistant`、消息类型与枚举值，`ready` 也执行相同校验。切换只更新布局和视图，保持 React 会话、输入草稿、流、滚动锚点及当前问题。图表容器 resize 后重新布局。新页由 React 的嵌入配置决定可见区域，旧页的 `MutationObserver`、DOM 贴片和 fetch 拦截只在旧页使用。[现有消息合同](../../bi_agent/web/static/cockpit/assistant.js) · [旧子页实现](../../bi_agent/web/static/analysis360-assistant.mjs)

### 3.3 360 聊天、澄清和看板数据

| 交互 | 继续使用的服务契约 |
| --- | --- |
| 360 自由提问 | 直接 `POST /api/analysis360/chat`，发送 `message`、显式 `session_id`、`analysis360_direct: true`。首轮绑定无条款的 360 run，后续用同一 ID。 |
| AskUser | `POST /api/analysis360/choice`，同一 `session_id`，按现有字段发送 `choice_ids` 和 `choice_labels`。 |
| 既有关联分析 | 现有 `/api/analysis360/handoff` 交接路径独立保留。旧编号不传给自由提问模式。 |
| 元数据和结果 | 只读取已允许的元数据及当前 360 流能提供的产物。同一轮的图表、链接与 SOP 用原 `turn_id`、工具 ID 或证据 ID 关联。 |

将现有 SSE 客户端改为可注入的 360 transport，通过 `useExternalStoreRuntime` 投影成 AgentKit 消息。先录制三份脱敏真实接口夹具，覆盖直接提问、带 AskUser 的续流和查询拒绝。对齐实际事件名、正文增量、SOP 数据、工具输入/结果、终态、错误和产物载荷，再接入状态 reducer。用 `session_id + generation` 隔离旧请求，用 `turn_id`、工具 ID 和事件身份把片段并入正确回合。澄清续流拥有自己的请求身份，仍归属原问题。断网、并发提问或切换会话后禁止重复发送已受理请求；流退出、错误、终态分别处理。关闭面板只隐藏界面。如果要在输入框提供「停止生成」，先验证 360 服务端能只停止当前 turn，再发布该按钮。[现有 360 聊天和澄清接口](../../bi_agent/web/app.py)

### 3.4 历史和客户入口的边界

基线的 `CustomerSurface` 放行 `/workbench`、`/api/meta` 和 `/api/analysis360/*` 等特定路径，通用 `/api/conversations*` 在客户入口不可达。通用历史激活也可能还原成常规工作台会话，360 的运行上下文与证据主要在服务端内存。新版的历史交付分为以下两类。

- 优先复用现有会话身份与 iframe 生命周期，接通收起、重开、刷新及多轮继续。刷新通过当前浏览器会话中已绑定的 ID 找回仍有效的原 360 会话。遇到进程重启后丢失原 360 run 或待澄清，说明恢复状态和可执行的下一步，保留已存的消息或结果。
- 可跨刷新/进程回看的历史如果需要新增接口，限定在 `/api/analysis360/`。复用现有会话仓库的数据结构和旧历史解析，加服务端确立并核验的 360 类型、存储归属和有限投影；允许访问的旧数据就地读取。无法确认归属或类型的老记录不纳入助手历史，具备读取授权的旧 360 记录可以回看。要允许继续时，必须从可信信息恢复 360 身份、允许的上下文和有效的待澄清状态。任何新增路径都有专属方法、归属和旧记录兼容测试。

客户入口对通用聊天、澄清、历史、报表、数据源和模型配置维持现有服务端限制。嵌入页面只显示后端已提供的能力。新 UI 不需要迁移或改写历史文件，切换或回退使用同一个挂载卷。兼容旧内容的 HTML 经过安全渲染，禁止把历史存储交给宿主直接输出。[客户入口](../../bi_agent/web/customer.py) · [360 会话和现有回看限制](../analysis360.md)
