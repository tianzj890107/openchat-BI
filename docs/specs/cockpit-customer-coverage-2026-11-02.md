# 客户覆盖标签与报价状态修复（2026-11-02）

## 展示口径

商机覆盖插槽恢复橙色“有商机未投标”和红色“无商机”两个标签。用户确认前者指“有商机但当前未投标”，不指历史上从未投标。数量由程序统计，模型不参与计数，也不使用原型 13/7、PACK 商机数、金额、分页样本行数代替客户数。

使用真实 AP 协议，由已冻结的 `YWLN_M0075` 客户数查询继承原始 commonConfig 筛选。固定发出两个只读查询：同范围客户去重总数；按具体客户、客户有无商机、是否投标中分组的客户数。后者最多返回 2000 行，不循环翻页。保留 AP 独立认证、身份隔离、并发限额、查询凭据；两个查询共享 20 秒总预算，失败不阻止原分析交付。

AP 需要支持：

- `YWLN_M0075`：COUNT DISTINCT 客户主数据客户 ID，包含无商机客户。
- `YWLN_D006`：必须在单元格返回稳定的 identifierNumber，名称不能充当主键。
- `YWLN_D_CUSTOMER_HAS_OPPORTUNITY`：客户级“有／无商机”状态。
- `YWLN_D_IS_BIDDING`：客户级当前是否投标中；同一客户多个商机必须由 AP 按“任一商机在投标中即为是”归并。

只有完整明细按 ID 去重数等于独立客户总数、字段完整且同客户状态不冲突时，才发布两个数量。未知状态、分页截断、姓名无 ID、口径冲突等返回 unavailable，计数为 null，不能显示假零。空全集总数明确为零时可以显示零。此口径是当前 AP 筛选的客户集合，不冒充已批准的年度计划客户全集或计划覆盖率。两次查询存在装载时差；总量对账不是数据库事务快照，结果保存两条凭据及取数时间，可追溯核查。

## 缓存与交付

统计在商机分析后台工作线程运行，customerCoverage 随分析结果持久化、发布和压缩交付。浏览器读取发布缓存，不自行查库、调用模型或重新统计。其他节点、厂家组件、交付元数据与头盔图不修改。

此修改不会覆盖已有分析。后续授权部署后，需对商机范围重新生成一次发布结果，旧卡片不会凭空获得新字段。AP 未支持这些维度或客户全集时只显示统计缺失，不承诺已恢复两个真实数量；需做真实 AP 联调验证。实现测试使用合成数据，不代替真实 AP 数据口径验收。本轮不部署、不执行线上预热。

## 报价修复

线上只读发布接口确认报价原始记录存在，值为正常完成 25.57、逾期完成 0.56、逾期未完成 0.60 GWh。旧解析只接受英文状态编码，导致全部显示“未返回”。增加五种中文办理状态到既有英文状态的显式映射，兼容旧编码、合法零值和缺失值。已有缓存无需重新调用模型即可恢复展示；缺失的临期与正常未完成继续显示未返回。

## 验证

Python 验证涵盖 ID 去重、同名客户、分页／总量不完整、缺失及冲突状态、真实零值、原筛选继承、快照隔离、统计压缩交付、查询共享预算与失败隔离。Node 验证覆盖英文与线上中文状态、零值及缺失状态。
