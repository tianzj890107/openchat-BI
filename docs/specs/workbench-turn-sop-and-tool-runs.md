# 每轮 SOP 与连续工具记录

用户要求：分析 SOP 在每轮问题后、回答前；连续工具调用持续追加，不因为模型迭代而拆成多条执行记录；仅可见正文输出形成分段，并减少留白。

- 每个新问题后插入独立 `turn-sop`，仍使用 Pro UI Activity/ExecutionSteps、默认折叠。按轮次保留 SOP 状态快照，后续问题不会覆盖前一轮。
- 原固定顶部/看板 SOP 不再重复显示；六阶段状态机与轮次导航继续复用。
- 工具连续执行时复用当前时间线。内部 iteration_start 不单独产生用户可见分段；有正文输出后，下一个工具段才重新开始。
- 首次正文到达时放到其前已执行工具的后面，维持事件顺序；新模型迭代先结束上一段正文的光标，避免额外空行。
- 工具详情保持原 Pro UI ToolCall 与命中本体点击入口。
- 工具记录以用户轮次和 activity id 定位，两个问题复用同一个工具 id 也不会互相覆盖。
- 缩小聊天段落间距、摘要外边距及正文留白，隐藏空的助手占位。

新快照含每轮 SOP 数据，恢复时重建组件。早期历史没有保存各轮 SOP 状态，不能凭空补造全部旧轮次的阶段轨迹；原会话内容保留。

隔离流式回放：连续三次模型迭代、每次两个工具，得到一个六项工具段；正文后两个工具得到第二段；第二轮复用同样工具 id 时，两轮各自保留六项与两项记录。SOP 均紧随对应用户问题、默认折叠、顶部重复 SOP 为零。
