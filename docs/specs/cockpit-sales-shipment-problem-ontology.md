## 1. 卡片定位

「穿透式分析 → 销售额与出货量共同分析」卡片按“指标 → 问题”驱动，只交付问题层（不交付根因与建议）。
问题按销售额口径的三个环节分为父节点，与头盔图「商机 → 订单 → 订未发」一致，结构与「商机获取 · 销售额口径明细」
卡片的风险分类相同：

| 父节点 | 子问题 | 判定方式 |
|---|---|---|
| 商机问题 | IS09 商机覆盖问题 | 关联商机获取卡片「商机覆盖风险」分类（RK01～RK07） |
| 商机问题 | IS10 商机转化问题 | 关联商机获取卡片「商机转化风险」分类（RK10、RK11） |
| 商机问题 | IS02 全年预计达成缺口 | 本卡片指标：预计销售额 / 出货量达成率 |
| 商机问题 | IS07 重点客户电量缺口 | 本卡片指标：战略 / 重要大客户电量缺口 |
| 订单问题 | IS03 销售额与出货量量价背离 | 本卡片指标：销售额与出货量达成率差 |
| 订单问题 | IS05 在手订单不足以覆盖剩余目标 | 本卡片指标：剩余目标订单覆盖率 |
| 订单问题 | IS08 订单取消／变更冲减 | 本卡片指标：取消 / 变更订单电量 |
| 订未发问题 | IS01 销售额与出货量双双落后时间进度 | 本卡片指标：销售额、出货量达成率与时间进度 |
| 订未发问题 | IS04 超期订未发积压 | 本卡片指标：超期订未发金额及占比 |
| 订未发问题 | IS06 订单履约率偏低 | 本卡片指标：订单履约率 |

DQ01～DQ06 为**数据校验**（取数失败、结果为空、口径不一致等），只用于判断数据是否可用，不作为业务问题展示，
也不交给模型判断；取数失败在卡片「数据范围」限制中说明。

## 2. 与商机获取卡片的关联（IS09 / IS10）

- 商机获取卡片（销售额口径明细）按自己的本体判定 RK01～RK11，并归为「商机覆盖风险」「商机转化风险」两个分类。
  本卡片不重复这些判定，也不另设指标：IS09 / IS10 的判定参数 `upstreamCategory` 指定读取哪个分类。
- **成立**：商机获取卡片同期间最新发布结果中，该分类下至少 1 项风险成立。
- **等级**：取该分类已成立风险的最高等级（极高 > 高 > 中 > 低）。
- **描述**：业务语言，列出成立风险的名称与等级，并附该分类的总结，例如
  「商机获取环节有 2 项商机覆盖风险成立：商机预测覆盖不足（高）、签单进度滞后（极高）。……」；不出现编码。
- **证据**：每条成立风险记为一条证据记录（`ss:upstream:opportunity-risk:<风险编码>`）。
- **无法判定**：商机获取卡片尚未发布同期间结果（或期间不一致）时，IS09 / IS10 不判定、不交给模型推断，
  卡片限制中提示「商机获取卡片尚未发布同期间分析结果，商机覆盖、商机转化问题暂未纳入」。
- **运行顺序**：客户年度模式整页分析时，商机获取卡片（`opportunity-risk`）排在共同分析卡片（`combined`）之前；
  单独重新分析共同分析卡片时，读取商机获取卡片的最近一次发布结果。

## 3. 卡片展示

- 标题「销售额与出货量共同分析」；顶部总述为业务语言，例如「本期发现 5 项业务问题：商机问题 2 项、订单问题 1 项、
  订未发问题 2 项。」，未发现时为「本期未发现商机、订单和订未发环节的业务问题。」。
- 每个父节点附一段分类总结：由模型按该分类已展示的问题生成，数字须来自该分类条目；校验未通过时改用规则总结
  （列出本类问题名称与等级），`riskGroups[].summarySource` 标注 `model` / `rule`。
- 卡片文字不显示本体编码（前端 `stripOntologyCodes` 统一过滤）；编码仅保留在本体追溯与证据中。

## 4. 本体与配置维护

1. 修改 `scripts/build_sales_shipment_ontology.py`（问题定义、`ISSUE_CATEGORY` 分类、关联分类参数），
   运行生成 V3 工作簿（需要 `openpyxl`、`pglast`，以及脚本头部列出的三个输入文件）。
2. 运行 `python scripts/build_sales_shipment_config.py` 生成运行配置；`判定参数` 含 `upstreamCategory`
   的问题生成为 `kind: "link"`，触发指标为空；`问题类型` 为「数据校验」的生成为 `kind: "data"`。
3. 运行配置版本须与 `bi_agent/cockpit/sales_shipment.py` 的 `RULES_VERSION` 一致，否则卡片拒绝运行。

## 5. 主要代码

- `bi_agent/cockpit/sales_shipment.py`：`evaluate()`（本卡片指标判定、IS09/IS10 关联判定、数据校验），
  `build_card()`（父子分组、分类总结、业务总述、限制说明）。
- `bi_agent/cockpit/frozen.py`：`_published_for_period()` 读取同期间商机获取卡片发布结果，`priority_order()` 运行顺序。
- `bi_agent/web/customer.py`：向分析执行器提供已发布卡片读取。
- `bi_agent/web/static/cockpit/insight-components/sales-shipment-issues/index.js`：卡片标题与展示选项。
