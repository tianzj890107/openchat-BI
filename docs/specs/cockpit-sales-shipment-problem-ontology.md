## 1. 卡片定位

「穿透式分析 → 销售额与出货量共同分析」卡片按“指标 → 问题”驱动，只交付问题层（不交付根因与建议）。
问题按销售额口径的三个环节分为父节点，与头盔图「商机 → 订单 → 订未发」一致；卡片固定显示商机、订单、发货三行，
每行一句话（商机获取本体 1117 BR-V01）。

| 父节点 | 子问题 | 判定方式 |
|---|---|---|
| 商机问题 | IS11 商机预测覆盖不足 | 1117 RK01：OR01（1117 R01）缺口＝年度目标－（进度＋预测）> 0 |
| 商机问题 | IS12 客户预测不足 | 1117 RK06：OR08（1117 R08）风险专用正缺口汇总，正缺口客户数 > 0 |
| 商机问题 | IS13 商机推进超期，影响签单 | 1117 RK11：OR12～OR17（1117 R12～R17）严重超期 OR13 / OR15 / OR17 任一 > 0 |
| 订单问题 | IS03 销售额与出货量量价背离 | 本卡片指标：销售额与出货量达成率差 |
| 订单问题 | IS05 在手订单不足以覆盖剩余目标 | 本卡片指标：剩余目标订单覆盖率 |
| 订单问题 | IS08 订单取消／变更冲减 | 本卡片指标：取消 / 变更订单电量 |
| 订未发问题 | IS01 销售额与出货量双双落后时间进度 | 本卡片指标：销售额、出货量达成率与时间进度 |
| 订未发问题 | IS04 超期订未发积压 | 本卡片指标：超期订未发金额及占比 |
| 订未发问题 | IS06 订单履约率偏低 | 本卡片指标：订单履约率 |

DQ01～DQ05 为**数据校验**（取数失败、结果为空、口径不一致等），只用于判断数据是否可用，不作为业务问题展示，
也不交给模型判断；取数失败在卡片「数据范围」限制中说明。

## 2. 商机部分（V4，同步亿纬锂能本体文件_1117）

- 1117 的 R01、R08、R12～R17 以 OR01、OR08、OR12～OR17 收录（本卡片的 R01～R10 已另有含义），调用SQL原样同步，
  以三个绑定参数 `[期初, 次年初, 观察日]` 执行；OR12～OR17 共用一次执行（OR12 的 SQL 把末尾
  `WHERE code = 'R12'` 放宽为六个分档）。
- 判定、等级与描述口径与商机获取卡片一致，不再读取商机获取卡片的发布结果：
  - **IS11**：金额、电量分别判断；缺口率 ≥ 10% 高、5%～10% 中、< 5% 低（判定参数 `gapRateHigh` / `gapRateMedium`）。
    描述「金额目标 X 亿元，进度 Y 亿元（1—M-1月已签单）＋预测 Z 亿元（M—12月），缺口 G 亿元，缺口率 r%。」。
  - **IS12**：只读 R08 明细中的「风险专用正缺口汇总」（先按客户合计，再分金额、电量取正缺口客户）；
    缺口客户含战略客户 高，其他已核实客户 中，客户等级未知时等级待核实。
  - **IS13**：只以严重超期（≥ 1.5 倍固定基线）成立；命中 ≥ 2 个阶段 高，否则跨阶段去重预测金额 ≥ 10 亿元 高、
    < 10 亿元 中，金额缺失或仅部分合计时等级待核实（判定参数 `stagesHigh` / `amountHigh`）。描述给出跨阶段按商机
    去重的严重超期商机数及最终叠加的预测金额、电量。
- 1117 中这三个风险的根因 RC01、RC07～RC13 与行动建议收录为 RC13～RC20、AC14～AC22（AI 判定，本卡片不运行）；
  只被引用、本卡片不取数的 1117 指标写作「1117·编码」。
- 已删除：IS02 全年预计达成缺口、IS07 重点客户电量缺口、IS09 商机覆盖问题、IS10 商机转化问题、数据校验 DQ06，
  指标 C01～C08、C10、R04～R07，根因 RC07 与建议 AC07。RC01 上游商机预测覆盖不足改按 OR01 判定，
  RC02 签单转化滞后改按 OR13 / OR15 / OR17 严重超期判定（仍是 IS01、IS05 的候选根因）。

## 3. 卡片展示

- 标题「销售额与出货量共同分析」；只显示商机、订单、发货三行，每行一句话：优先用模型的分类总结（按一句话生成），
  没有模型总结时列出该环节问题，没有问题时写「本期未发现…」或「数据不足，无法核实」。
- 卡片文字不显示本体编码（前端 `stripOntologyCodes` 统一过滤）；编码仅保留在本体追溯与证据中。

## 4. 本体与配置维护

1. 订单、发货部分：修改 `scripts/build_sales_shipment_ontology.py` 生成 V3 工作簿（需要 `openpyxl`、`pglast`
   及脚本头部列出的三个输入文件）。
2. 商机部分：运行 `python scripts/build_sales_shipment_ontology_v4.py`，在 V3 上同步《亿纬锂能本体文件_1117》
   的商机风险、指标、根因、建议与 SQL 计算步骤，生成 V4 工作簿。
3. 运行 `python scripts/build_sales_shipment_config.py` 生成运行配置；`问题类型` 为「数据校验」的生成为
   `kind: "data"`；带调用SQL的指标即使类型为「派生指标」也按SQL取数。
4. 运行配置版本须与 `bi_agent/cockpit/sales_shipment.py` 的 `RULES_VERSION` 一致，否则卡片拒绝运行。

## 5. 主要代码

- `bi_agent/cockpit/sales_shipment.py`：`metric_sql()`（分档共用语句）、`collect()`（1117 SQL 绑定参数）、
  `_opportunity_issues()`（IS11～IS13）、`evaluate()`（订单、发货问题与数据校验）、`build_card()`（父子分组、三行总结）。
- `bi_agent/web/static/cockpit/insight-components/sales-shipment-issues/index.js`：卡片标题与展示选项。
