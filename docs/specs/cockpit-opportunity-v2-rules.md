# 商机获取节点 V2 规则卡实现说明

## 目标

`opportunity-risk` 卡以《亿纬锂能_本体_商机获取节点_V2》为准，独立读取客户数据库、执行固定规则并发布，不再复用共享 `opportunity` 阶段卡片。程序负责阈值、数值、规则触发与候选关系；每轮调用一次模型，由模型结合规则结果和证据生成摘要、风险说明、原因和建议，程序再校验代码、数字、证据与关联边界。

## 运行链路

1. `scripts/build_opportunity_v2_config.py` 从 V2 本体和数据字典生成并校验 `bi_agent/cockpit/assets/opportunity-v2/config.json`，保留源文件 SHA256、25 个指标、10 类风险、8 类原因、8 类建议和风险关联。
2. `bi_agent/cockpit/opportunity_v2.py` 只使用已校验的表字段映射和参数化 SQL，读取目标、月度预测、合同确认、客户等级、产品、阶段、投标、订单关系、项目进展和团队关系。所有数据库查询在同一个 `REPEATABLE READ` 快照内完成；每条查询使用独立 savepoint，单条 SQL 失败回滚后不污染同快照的后续可选查询。
3. 程序计算指标并执行 RK01～RK10；金额和电量分别计算，不互相折算；动态周期严格大于同阶段、同产品类型均值的 1.5 倍才判超期。
4. 每次规则计算后调用一次模型。输入包括全部 RK01～RK10 候选、每个候选的 `ruleStatus=triggered/not_triggered/indeterminate`、规则原文、已观测事实、缺失输入、本体允许的原因/建议候选和对应进展片段；程序不先筛掉未命中风险。模型逐条判断证据是否足以支持风险，可标记 `confirmed/structural/insufficient/not_applicable`，并分别引用支持证据与反对（反例）证据，再生成摘要、原因和建议。只有程序已触发且模型确认的风险可以展示；模型不能把程序计算的未命中数值规则改判为成立，对已触发规则可以降级为证据不足或结构表现。程序校验风险/原因/建议代码、风险—原因—建议关联、数字只能来自输入、支持与反对证据必须可追溯且不得使用“逾期未完成”。越界项拒绝；模型失败时保留程序规则生成的完整降级文本，规则结果与逐条证据仍正常发布。
5. `opportunity-risk` 作为独立 publication key 写入冻结年度版本。前端只读取该 slot 自己的已发布 payload，不再用共享阶段 `state.item` 按时间戳与之比较；点击该卡的“重新分析”只刷新 `opportunity-risk` 队列项。整页重算时商机节点的分阶段卡片交给独立分析流程更新，`opportunity-coverage-note` 和其他卡片继续使用共享 `opportunity` 结果。共享卡晚于专用卡完成、专用卡晚于共享卡完成两种顺序都有回归测试。
6. 专用分析通过同一个进度回调依次上报“读取本体 → 查询数据库（完成数/总数）→ AP 补充（如需要）→ 规则计算 → 原因分析 → 发布”；前端固定按 `opportunity-risk` 读取该卡进度和耗时，不跟随历史发布结果中的共享 `opportunity` 键。
7. 冻结发布卡不写入普通分析历史表。草稿与任务下发通过年度发布版本按 `analysis id` 回查完整卡片、证据和建议，避免返回“分析记录不存在”。

## 固定口径

- 签单按 `new_contractconfirmation=1` 判断；`0` 为未确认，空值或其他值不当作零值或已签。
- 已确认签订覆盖率（实现口径）为“合同已确认商机预测 ÷ 目标”，金额和电量分别计算；合同状态未知既不进入已签，也不进入明确未签或进度滞后触发。季度待签窗口只使用明确未确认金额或电量加预测缺口。
- 客户等级：战略 `0/1`、重点 `2/4`、一般 `3`，其他值不推断。
- 项目阶段只映射 `11～15 → P0～P4`。
- 目标表按行求和，不按客户或产品做无业务键依据的 `DISTINCT`。
- 目标字段全部为空时保留 `NULL`，表示“未取得目标”，不转成 0；数据库返回的真实 0 是有效值，可以与空值区分。
- 预测电量使用覆盖稳定的 `new_orderforecast_qty`（kWh）换算 GWh；`new_forcastpower` 的实库空值只在限制中披露。
- 商机、投标和进展按测量日过滤；在途记录算至测量日，完成记录算至结束时间。目标、订单等无业务时间键的数据不做无依据的时间截断，并在口径中说明。
- 查询结果达到行数上限时标记 `ROW_LIMIT` 并将卡片置为 `limited`；展示明细可以截断，但金额、电量、合同、产品、客户和风险总量只使用全量聚合。全量聚合本身失败时，截断明细不参与这些计算，相关规则不触发。
- 投标关联仅使用去首尾空格后的精确项目名称。同名多条记录判为歧义，不据此认定“未投标”。
- “有商机未投标”只统计当前在推商机；历史商机不遮挡当前问题。
- 需求未确认只接受明确状态 `1/2/4/5`；状态为空表示未知，不默认算作未确认。
- 战略客户无商机区分“从未建立商机”和“历史有商机、当前无在推商机”。RK07 的原因候选不再关联 RC01，避免同一客户范围内出现互相矛盾的条件。
- RC04、RC05 只作结构定位，不单独证明待签或转化受阻。
- 任一规则依赖事实为空且程序未触发时，`ruleStatus` 为 `indeterminate`，不得当作 `not_triggered`；模型只能判为证据不足，不能确认风险成立。
- 模型判断结果逐条写入 `riskAssessments`，包含 `include/classification/evidenceIds/supportingEvidenceIds/opposingEvidenceIds`。最终未展示的候选写入 `excludedRiskCodes`，模型主动排除项另写 `modelExcludedRiskCodes`。

## 失败与降级

- 单个可选查询失败时保留其他已取证据，依赖缺失指标的规则不触发，卡片状态为 `limited`。
- 目标、商机、客户等核心查询全部失败且没有任何可保留证据时，本轮不发布，冻结版本继续使用上次成功卡片。
- 数据库真实零值和规则未触发是有效结果，不以 AP 或模型补造风险。
- AP 只补数据库缺失的聚合指标，不替换数据库成功返回的值，也不补造商机明细、合同状态或原因文本。当前仅映射语义一致的 `目标销售额`、`商机获取金额`、`商机获取电量`；`目标出货量` 和 `待突破战略客户数` 与 V2 指标语义不一致，不参与补充。
- 可通过 `COCKPIT_OPPORTUNITY_V2_AP_SUPPLEMENT=0` 关闭 AP 补缺；关闭后数据库缺失指标的规则保持不触发，卡片按已有证据以 `limited` 发布。
- 数据库返回真实零值或规则未触发时不再请求 AP；只有字段缺失、查询失败、覆盖不足或行截断才进入补缺路径。
- 项目进展文本用于模型解释已触发风险的原因，不参与风险阈值判定；模型不可新增风险、原因或建议代码。
- 风险卡正文中的数值与单位按共同问题分析卡样式统一显示为蓝色强调；建议条目不展示责任角色占位文本。

## 验收

- `tests/test_cockpit_opportunity_v2.py`：配置完整性、合同确认口径、客户等级、动态周期严格阈值、投标同名歧义、建议反查、每轮模型调用、10 个候选风险全部送入模型、模型逐条判断与支持/反对证据、未触发规则不可改判成立、已触发规则可降级、缺失目标时不得确认 RK01、越界代码/数字/证据/关联拒绝、目标行求和、空值与零值区分、当前在推商机口径、截断明细/全量聚合、AP 聚合补缺、部分查询失败和核心失败。
- `tests/test_process360_db_savepoint.py`：同一快照中单条 SQL 失败后回滚 savepoint，后续查询仍可继续。
- `tests/test_cockpit_frozen_annual.py`：独立卡片发布、独立验证、证据页、单卡刷新不覆盖共享商机卡、共享/专用两种完成顺序互不覆盖、冻结卡可按分析 id 生成任务令草稿。
- `tests/cockpit_publication_selection.test.mjs`：专用卡只认 `opportunity-risk` 发布，不读取共享商机阶段结果。
- `tests/cockpit_stage_risk_format.test.mjs`：风险/原因/建议数字与单位蓝色强调，建议条目不渲染责任角色占位。
- 实际客户只读库试跑：25 个指标配置加载成功，当前 2026 年度卡片可生成，风险、原因、建议均带证据和风险关联。
