# 商机获取节点 V2 规则卡实现说明

## 目标

`opportunity-risk` 卡以《亿纬锂能_本体_商机获取节点_V2》为准，独立读取客户数据库、执行固定规则并发布，不再复用共享 `opportunity` 阶段卡片。风险、阈值、原因候选和建议关系由本体配置与程序规则生成；模型只解释项目进展文本和改写建议措辞。

## 运行链路

1. `scripts/build_opportunity_v2_config.py` 从 V2 本体和数据字典生成并校验 `bi_agent/cockpit/assets/opportunity-v2/config.json`，保留源文件 SHA256、25 个指标、10 类风险、8 类原因、8 类建议和风险关联。
2. `bi_agent/cockpit/opportunity_v2.py` 只使用已校验的表字段映射和参数化 SQL，读取目标、月度预测、合同确认、客户等级、产品、阶段、投标、订单关系、项目进展和团队关系。所有数据库查询在同一个 `REPEATABLE READ` 快照内完成；每条查询使用独立 savepoint，单条 SQL 失败回滚后不污染同快照的后续可选查询。
3. 程序计算指标并执行 RK01～RK10；金额和电量分别计算，不互相折算；动态周期严格大于同阶段、同产品类型均值的 1.5 倍才判超期。
4. 只对本卡已展示风险选择原因；模型输入被限制在已触发风险、已选原因、建议代码和对应进展片段内。模型失败、返回新数字/新原因/新建议，或原因未引用输入中的 `progressSamples.evidenceId` 时，该原因不采用；规则风险和逐条证据仍正常发布。
5. `opportunity-risk` 作为独立 publication key 写入冻结年度版本。刷新该卡只替换独立结果；`opportunity-coverage-note` 和其他卡片继续使用共享 `opportunity` 结果。

## 固定口径

- 签单按 `new_contractconfirmation=1` 判断；`0` 为未确认，空值或其他值不当作零值或已签。
- 客户等级：战略 `0/1`、重点 `2/4`、一般 `3`，其他值不推断。
- 项目阶段只映射 `11～15 → P0～P4`。
- 目标表按行求和，不按客户或产品做无业务键依据的 `DISTINCT`。
- 目标字段全部为空时保留 `NULL`，表示“未取得目标”，不转成 0；数据库返回的真实 0 是有效值，可以与空值区分。
- 预测电量使用覆盖稳定的 `new_orderforecast_qty`（kWh）换算 GWh；`new_forcastpower` 的实库空值只在限制中披露。
- 商机、投标和进展按测量日过滤；在途记录算至测量日，完成记录算至结束时间。目标、订单等无业务时间键的数据不做无依据的时间截断，并在口径中说明。
- 查询结果达到行数上限时标记 `ROW_LIMIT` 并将卡片置为 `limited`；展示明细可以截断，但金额、电量、合同、产品、客户和风险总量只使用全量聚合。全量聚合本身失败时，截断明细不参与这些计算，相关规则不触发。
- 投标关联仅使用去首尾空格后的精确项目名称。同名多条记录判为歧义，不据此认定“未投标”。
- “有商机未投标”只统计当前在推商机；历史商机不遮挡当前问题。
- 需求未确认只接受明确状态 `1/2/4/5`；状态为空表示未知，不默认算作未确认。
- 战略客户无商机区分“从未建立商机”和“历史有商机、当前无在推商机”。RK07 的原因候选不再关联 RC01，避免同一客户范围内出现互相矛盾的条件。
- RC04、RC05 只作结构定位，不单独证明待签或转化受阻。

## 失败与降级

- 单个可选查询失败时保留其他已取证据，依赖缺失指标的规则不触发，卡片状态为 `limited`。
- 目标、商机、客户等核心查询全部失败且没有任何可保留证据时，本轮不发布，冻结版本继续使用上次成功卡片。
- 数据库真实零值和规则未触发是有效结果，不以 AP 或模型补造风险。
- AP 只补数据库缺失的聚合指标，不替换数据库成功返回的值，也不补造商机明细、合同状态或原因文本。当前仅映射语义一致的 `目标销售额`、`商机获取金额`、`商机获取电量`；`目标出货量` 和 `待突破战略客户数` 与 V2 指标语义不一致，不参与补充。
- 可通过 `COCKPIT_OPPORTUNITY_V2_AP_SUPPLEMENT=0` 关闭 AP 补缺；关闭后数据库缺失指标的规则保持不触发，卡片按已有证据以 `limited` 发布。
- 数据库返回真实零值或规则未触发时不再请求 AP；只有字段缺失、查询失败、覆盖不足或行截断才进入补缺路径。
- 项目进展文本只用于解释已触发风险的原因，不参与风险阈值判定；模型不可新增风险、原因或建议代码。

## 验收

- `tests/test_cockpit_opportunity_v2.py`：配置完整性、合同确认口径、客户等级、动态周期严格阈值、投标同名歧义、建议反查、模型越界与证据编号拒绝、目标行求和、空值与零值区分、当前在推商机口径、截断明细/全量聚合、AP 聚合补缺、部分查询失败和核心失败。
- `tests/test_process360_db_savepoint.py`：同一快照中单条 SQL 失败后回滚 savepoint，后续查询仍可继续。
- `tests/test_cockpit_frozen_annual.py`：独立卡片发布、独立验证、证据页、单卡刷新不覆盖共享商机卡。
- 实际客户只读库试跑：25 个指标配置加载成功，当前 2026 年度卡片可生成，风险、原因、建议均带证据和风险关联。
