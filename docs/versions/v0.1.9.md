# 智能分析 v0.1.9

## 基本信息

- 版本：`v0.1.9`
- 日期：`2026-09-17`
- 状态：正式版 / 当前版本
- Git Tag：`v0.1.9`（annotated，指向本次发布提交）
- 定版 commit：tag `v0.1.9` 指向的发布提交（开发分支 `20260727`，经 Merge Request 合入 `master`）

## 版本概述

v0.1.9 把分析 Agent 的**评测资产**与**交付流水线**收口：黄金评测集从 291 条扩展到
482 条并引入 recorded-provider 回放层，GitLab CI/CD 正式接入项目 runner
`sys740-docker-runner` 并全绿，产品版本号按语义化版本统一升级到 `0.1.9`。

本版本没有新增用户可见业务能力，也没有修改分析 Agent 业务实现，按 PATCH 级发布
执行；补齐的是「改 Prompt / 模型 / SQL / 本体 / 图表 / 会话状态之后不会被无声回归
骗过」的评测与门禁能力。

## 交付主题

### 1. 黄金评测集扩展与 recorded-provider 回放层

- 评测集规模 291 → **482** 条（P0 107 / P1 340 / P2 35），其中 12 条为已登记缺陷的
  Red 用例（P0 6 条），未删除、未弱化任何原有案例；
- 新增 `scripts/analytics_recorded_provider.py` 回放执行器：录制事件经**真实**
  `WebSession.generate_turn` 会话循环回放，使用生产工具注册与工具参数校验、生产
  SSE/事件解析，SQL 工具改向只读 eval SQLite fixture，会话/图表/日志全部写入
  `tempfile.mkdtemp` 临时目录，API key 固定为测试值，不访问网络；
- 新增 evaluator：`recorded_provider`、`generated_sql`、`tool_chain`、
  `answer_grounding`、`context_resolution`；离线回归由此从「预置 SQL 执行」升级为
  「真实会话 + 真实工具 + 真实 SQL 生成链路」；
- 数字接地改为**案例级**（`RecordedPool`）：删除原先把全部 SQL 案例结果与
  0–119、180、2024、2025 等数字放进全局 `allowed_numbers` 的兜底，跨案例数字不再
  被误判为已引用；并新增反向对照案例证明「其他案例出现过的数字」在本案例仍属
  unsupported；
- 财务、制造补齐独立数值 fixture：`fixtures/sqlite/finance.db`（29 条数值案例）与
  `fixtures/sqlite/manufacturing.db`（30 条数值案例），由 `build_fixtures.py`
  可重复生成；本体工作簿同步扩充；
- known_gap 治理：登记 `owner` / `introduced_at` / `target_fix_version` /
  `severity` / `source_issue`，新增 `known_gap_allowlist.json`（按 case_id，发布门禁
  专用）、`known_gap_ratchet.json`（12 / 6，不允许增长）与 xpass 门禁；报告不再把
  「103 条 P0 中的 97 条通过」写成全部通过，改为输出 `p0_total` / `p0_passed` /
  `p0_failed` / `p0_xfailed` / `p0_xpassed` / `unresolved_p0_defects`；
- schema 加固：per-evaluator `if/then` 必填、`fixture.additionalProperties=false`、
  未知字段直接判失败、重复 `(question, evaluator, expected)` 检测、生成器可重复性
  对比测试。

### 2. GitLab CI/CD 接入项目 runner

- `.gitlab-ci.yml` 定义 `test` / `eval` 两阶段，默认镜像
  `boulderai/analytics-ci:3.13`，所有 job 声明 `tags: [boulderai]` 以匹配
  「不执行 untagged job」的项目 runner；
- job：`unit-tests`（全量 pytest，排除依赖本地 npm 包的 1 个用例）、
  `analytics-eval-smoke`、`analytics-eval-regression`、
  `analytics-eval-recorded-provider`（离线、无需凭据），以及手动且
  `allow_failure` 的 `analytics-eval-release-gate`（P0 known gap 未被审计 allowlist
  覆盖时失败）；
- 运行节点：项目 runner `sys740-docker-runner`（`172.16.10.34`，docker executor）；
- pipeline 只做验证：没有 deploy stage，job 不写服务器，push 不触发部署；
- 实测当前提交的 pipeline（id `3142`）4 个 job 全部 `success`
  （unit-tests 75.6s、smoke 18.0s、regression 21.7s、recorded-provider 19.8s），
  release gate 保持手动未执行。

### 3. 产品版本号统一升级到 v0.1.9

- 统一升级版本入口：`pyproject.toml`、`bi_agent/__init__.py`、
  `open_claude/__init__.py`、FastAPI `APP_VERSION`、`frontend/package.json`、
  `frontend/package-lock.json`、`frontend/src/main.jsx` 的 `PRODUCT_VERSION`、
  `frontend/src/shell.html` 顶部品牌标签；
- 前端 vite 生产构建重建，产物与旧版差异仅为两处版本字符串（可见 UI 版本标签为
  `v0.1.9`）；
- 版本契约测试同步：`tests/test_versioning_policy.py` 断言产品版本为 `0.1.9`，官方
  tag 白名单放行 `v0.1.0`–`v0.1.9`；`tests/test_regressions.py` 品牌/版本一致性
  断言同步。

## 已知限制

- 6 条 P0 known gap 仍为未修复缺陷（仅登记，本版本不修改业务实现）；
- `live` 套件需要真实模型凭据，本版本**未运行**，也不计入离线门禁；
- 本版本未部署：tag 与 GitLab Release 不改变服务器正在运行的版本；
- 评测集中仍有部分用例只验证策略/校验函数（`policy`、`ontology`、
  `chart_validate`、`sql_guard`、`admission`、`chart_policy`、
  `session_isolation`、`chart_html_safety`），未覆盖完整 Agent 会话链路。
