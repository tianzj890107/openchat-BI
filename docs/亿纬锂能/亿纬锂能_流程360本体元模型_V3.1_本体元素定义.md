# 亿纬锂能流程360本体元模型 V3.1：本体元素定义

- 来源：同目录《亿纬锂能_流程360本体元模型_V3.1_新增数据表联动版.xlsx》的“元素目录”“使用说明”及对应工作表。
- 整理日期：2026-11-05。
- 范围：保留原文件的元素名称、编码前缀和语义，将简要定义展开为供产品、建模和研发对齐的表述。示例用于解释，不代表实际业务记录或已接通能力。

## 1. 本体元素定义

原文件“元素目录”共列出 **23 类元素**。

| 元素 | 编码前缀 | 定义 | 示例与边界 |
| --- | --- | --- | --- |
| 流程 | PR | 为实现某项业务目标，由多个活动及其协作关系构成的业务过程，可包含子流程。 | 发货流程；不是某一张发货单的执行记录。 |
| 活动 | AC | 流程中承担具体职责的业务操作节点，定义输入、输出、责任角色、前置条件和完成条件。 | 交期确认、质量放行、实际发货。 |
| 场景 | SC | 特定角色围绕某个业务问题开展分析与处置时的范围和上下文，关联流程、活动、对象及指标。 | 发货超期治理；不是一个页面或一次对话本身。 |
| 业务角色 | RO | 一组业务职责、数据范围及授权边界的定义，执行时需要解析到具体人员。 | 质量负责人；角色不等于某个员工或团队成员。 |
| 业务对象 | BO | 业务中需要识别、管理和追踪的事物，具有统一的业务含义。 | 商机、订单、客户、发货。 |
| 逻辑实体 | LE | 业务对象在逻辑数据层的结构化表达，明确记录粒度、标识、属性及关联。 | 订单、订单产品；一个业务对象可由多个逻辑实体表达。 |
| 业务属性 | AT | 描述逻辑实体某个特征的数据项，包含业务含义、类型及必要约束。 | 订单主键、约定交期、发货数量；不能仅凭物理字段名判断含义。 |
| 术语 | T | 对业务概念的统一语言定义，包括名称、别名和解释，用于消除理解歧义。 | “订未发”的统一含义；术语本身不等于计算公式。 |
| 指标 | M | 按确定口径计算，用于衡量业务规模、效率、质量或结果的量化度量。 | 实际销售额、实际出货量、报价平均周期；须明确粒度、单位、期间和来源。 |
| 维度 | D | 对指标和事实进行分类、筛选、分组及下钻的观察角度，可包含派生分类和层级。 | 月份、产品团队、客户等级、办理状态。 |
| 指标参照配置 | RF | 为指标比较提供目标、基线或阈值，并定义比较方式、单位、适用范围、版本及启用条件。 | 年度销售目标、报价周期基线、红区报价占比提醒线。 |
| 业务规则 | R／BR | 对业务计算、识别、判断、约束或复验进行规范的条件与结果定义。 | 超期识别规则、任务下发校验规则；中文规则说明不自动等于可执行代码。 |
| 异常 | AN | 按明确参照和规则，识别出的已经发生、可以观察和核对的业务偏差。 | 已超过约定交期仍未发货；不能把缺数据直接判成异常。 |
| 问题 | PB | 围绕需要解释和处置的业务事项，对相关异常、对象、责任与关闭要求进行组织的中心。 | 某客户订单持续交付延迟；一个问题可归并多条异常。 |
| 风险 | RK | 在某个未来时间窗口内，可能发生的不利业务后果，需要结合证据评估其范围、等级及影响。 | 延迟可能影响年度出货目标或引发索赔；风险不等于已经发生的损失。 |
| 原因因子 | CF | 用于解释异常或问题的候选业务机制，定义因果作用、所需证据及验证方法。 | 缺料、质量未放行、客户提货延迟；未经验证不能直接称为已确认根因。 |
| 影响 | IM | 异常或风险作用于业务目标、对象及结果的实际或潜在后果，可定量或定性描述。 | 受影响订单金额、潜在交付缺口；业务敞口不能直接当作损失金额。 |
| 证据 | EV | 支持、反驳或限定某项判断的可追溯来源依据，需明确对象、来源、时间和版本。 | 检验记录、订单行、客户确认附件；定义层保存证据模板，运行层保存具体证据。 |
| 解决方案 | SL | 针对原因、问题或风险，在约束条件下组织的一组处置措施，定义预期效果及相关动作。 | 补料、返工、复检与交付调整的组合；不是一句泛化建议。 |
| 动作 | AX | 可以在授权条件下调用或组织执行的业务操作，定义输入输出、前后条件、权限、审批和回执。 | 查询证据、下发任务令、申请复检；定义动作不代表已经接通执行接口。 |
| 任务令 | TK | 将方案或动作落实到具体对象、责任人员、期限、目标及验收要求的任务分派模板。 | 锁定排产与产能任务；实际下发后还需生成任务实例和回执。 |
| 复验 | VF | 对任务交付是否合格、业务效果是否达到目标进行验证的方法定义，引用原对象集合、指标、规则和证据。 | 原超期订单履约化解比例复验；完成任务不等于效果达标。 |
| 实体关系 | REL | 逻辑实体之间的关联定义，明确源实体、目标实体、关联属性、方向及关系基数。 | 订单与订单产品的一对多关系；不能用名称相似代替真实关联键。 |

## 2. 目标、基线、阈值

这三类内容目前归在“指标参照配置”中，没有分别列为独立元素类型。

| 概念 | 定义 | 示例 |
| --- | --- | --- |
| 目标 | 在指定期间和范围内，希望达到的业务结果。 | 年度出货目标。 |
| 基线 | 用于比较或评估变化的参考水平，可以是标杆或冻结的历史观测。 | 发货周期标杆、复验前冻结的原超期余额。 |
| 阈值 | 用于触发判断或划分区间的边界值。 | 超期判断边界、红区报价占比提醒线。 |

参照必须带适用范围和版本。演算示例或原型建议值不能直接作为客户批准目标。

## 3. 异常、问题、风险及原因的边界

| 概念 | 关注点 | 同一交付场景中的示例 |
| --- | --- | --- |
| 异常 | 已观察到什么偏差。 | 订单超过约定交期10天仍未发货。 |
| 问题 | 哪项业务事项需要调查、协调和处置。 | 某客户一批订单持续交付延迟。 |
| 风险 | 未来可能发生什么不利后果。 | 延迟可能引发索赔、影响年度出货目标。 |
| 原因 | 哪个业务机制导致或促成了偏差。 | 检验未放行导致该批订单无法发运；必须有对象和时间一致的证据。 |
| 影响 | 实际或潜在后果作用于哪些对象、指标，规模多大。 | 受影响订单金额、潜在目标缺口。 |

典型联系是“发现异常 → 归并问题 → 评估风险 → 核查原因 → 制定措施”，但不是强制的一对一链条：没有异常也可以提前识别风险，一个问题可以关联多条异常和多个风险。流程先后和统计相关不能直接证明因果。

“根因”没有单独列为元素类型。它是某个原因因子针对具体问题，经证据验证后形成的结论，不是原因模板天然具有的属性。

## 4. 建议、解决方案、动作和任务令的边界

“建议”没有单独列为元素类型。建议是分析阶段提出、供人确认的处置意见，可进一步关联或形成解决方案、动作及任务令草稿。

- 解决方案：组织采取哪些措施及其约束和预期效果。
- 动作：定义具体可执行的业务操作及输入输出、权限、审批和回执。
- 任务令：把方案或动作分派给具体对象和人员，约定期限、目标与验收要求。
- 复验：分别检查任务交付与业务效果，不把下发成功或任务完成直接认定为风险解除。

建议不代表授权执行；任务下发审批也不等于业务单据回写授权。

## 5. 定义与运行实例

定义层保存可复用的语义和约束；运行层保存某次业务分析与执行的真实记录，引用定义编码及版本。

| 定义层 | 运行层 |
| --- | --- |
| 发货超期治理场景定义。 | 某次发货超期分析的上下文和对象集合。 |
| 超期识别规则及其适用范围。 | 某订单行按该规则识别出的异常。 |
| 原因因子与证据模板。 | 本次原因假设、实际证据、支持或反驳结论。 |
| 方案和任务令模板。 | 任务草稿、确认记录、下发任务和执行回执。 |
| 复验定义。 | 基于冻结对象集合与指标口径形成的复验结果。 |

闭环样例与闭环演算是模拟记录，不是客户实绩或实际下发结果。

## 6. 其他工作表与独立元素的边界

本文件明确不设置“状态”“事件”两类独立本体元素。源业务状态、审批标记、任务进度和确认标记作为普通属性或运行字段保存。

以下工作表承担关系、映射、编排或契约配置职责，不应简单按工作表数量认定为新增元素类型：

| 工作表 | 用途 |
| --- | --- |
| 对象关系 | 业务对象之间的语义关联。 |
| 本体元素关联 | 不同类型元素之间的关系和约束。 |
| 逻辑实体映射、业务属性映射 | 逻辑语义到物理表和字段的映射。 |
| 指标维度矩阵 | 指标允许使用的维度声明，仍需验证真实关联。 |
| 维度派生配置、维度派生规则配置、维度层级配置 | 派生分类、关联和下钻层级。 |
| 规则节点绑定 | 规则与流程活动的适用关系和调用时机。 |
| 方案动作 | 方案中动作的顺序、依赖和参数映射。 |
| 运行记录契约 | 业务系统需要保存的运行字段及其约束。 |
| 待确认事项、校验结果、变更清单 | 接入限制、检查结论及变更依据。 |

是否可执行以执行许可和待确认事项为准；存在类型定义、关联关系或物理映射，不等于已经具备实际查询、审批或执行能力。
