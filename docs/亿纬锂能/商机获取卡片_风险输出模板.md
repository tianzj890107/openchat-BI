## 一、页面结构（本体 BR-V02～V05）

```
【风险】商机当前风险判断及根因分析
  ▌商机覆盖风险及根因分析            ← 分类标题，加粗醒目；不再显示“本类共 N 项风险：…”汇总行
    风险1  商机预测覆盖不足（规则判定 · 等级）——{描述}
      ▾ N 项根因（默认展开）
        根因1 【商机获取】{名称}（AI 分析 · 待核实）——{说明}
    风险2  客户预测不足（…）——{描述}
  ▌商机转化风险及根因分析
    风险3  商机推进超期，影响签单（…）——{描述}
       · 商机获取阶段 · 严重超期 · {n} 条 · 预测金额 · 预测电量   ← 只列严重超期，每阶段一行
      ▾ N 项根因
```

- 风险与根因的证据（识别的规则、取数 SQL）暂时隐藏；建议仍隐藏。
- 等级为空表示本体对该情形未定级或待核实，卡片只显示“规则判定”。
- 所有指标调用 SQL 以三个绑定参数执行：`[期初, 次年初, 观察日]`，例如 2025 年度、观察日 2025-10-31 时为 `[2025-01-01, 2026-01-01, 2025-10-31]`。

## 二、三个风险（BR-V06：签单进度滞后 RK02 及其专属根因已删除）

### RK01 商机预测覆盖不足（商机覆盖风险）

- **取数**：本体 R01 调用 SQL，只读总体（product_type = 全部）一行：目标、进度、预测、缺口、缺口率。
- **成立**：缺口 ＝ 年度目标 −（进度＋预测）> 0，金额、电量分别判断；进度＝观察月以前已签单商机预测，预测＝观察当月至 12 月全部商机预测。
- **等级**：成立一侧缺口率较大者 ≥ 10% 高；5%～10% 中；< 5% 低。
- **模板**：

```
金额目标 {目标} 亿元，已签单 {进度} 亿元（1—{M-1}月）＋预测 {预测} 亿元（{M}—12月），缺口 {缺口} 亿元，缺口率 {缺口率}%。
电量目标 {目标} GWh，已签单 {进度} GWh＋预测 {预测} GWh，缺口 {缺口} GWh，缺口率 {缺口率}%。
```

### RK06 客户预测不足（商机覆盖风险）

- **取数**：本体 R08 调用 SQL 明细中唯一的“风险专用正缺口汇总”。每个客户先合计全部年度目标、进度和剩余预测，再分别按金额、电量筛出正缺口客户；同一客户内部可抵扣，不跨客户抵扣。
- **成立**：任一口径正缺口客户数 > 0。
- **等级**：缺口客户中含战略客户 高；其他已核实客户 中；客户等级未知时为空（待核实）。
- **模板**（某一口径没有缺口客户时省略该口径）：

```
{n}家客户的已签单＋剩余预测低于客户目标：金额口径 {a} 家，目标 {x} 亿元，已签单 {x} 亿元＋剩余预测 {x} 亿元，缺口合计 {x} 亿元；电量口径 {e} 家，目标 {x} GWh，进度 {x} GWh＋剩余预测 {x} GWh，缺口合计 {x} GWh。
```

- 根因输入：C10（同一客户集合内战略、重点客户的商机储备及占比）、R09（截至日无商机的战略客户及其目标）。

### RK11 商机推进超期，影响签单（商机转化风险）

- **取数**：本体 R12～R17 阶段分档 SQL（一次执行），P0/P1/P2 已结束有效正周期逐笔对比固定基线 P0=32.6、P1=21.8、P2=7.2 天；R13/R15/R17 为严重超期（≥ 1.5 倍基线），R12/R14/R16 为超期。
- **成立**：R13、R15、R17 任一商机数 > 0。
- **等级**：命中 ≥ 2 个阶段 高；否则按跨阶段去重影响金额 ≥ 10 亿元 高、< 10 亿元 中；金额缺失或仅部分合计时为空（待核实）。
- **模板**：

```
{跨阶段去重商机数}条商机的阶段周期超基线50%及以上（严重超期），涉及预测金额合计 {x} 亿元、电量 {x} GWh（跨阶段按商机去重）。
```

- 金额、电量是最终叠加值：先按商机 ID 去重再汇总（BR-V09），不把各阶段金额直接相加。
- 描述下方只列严重超期的阶段行（商机获取、技术交流、方案推动各一行），超基线未满 50% 的超期档不显示。
- P0-09（截至观察日仍在 P0 的在途超期）只作根因输入，不计入上述合计。

## 三、根因（BR-L01，AI 全局分析）

- 风险判定后调用一次模型，输入为已成立风险的判定结果和指标事实（RK06 附 C10、R09；RK11 附 P0-09、P0-01、P0-02），每条风险给出 1～2 条根因，不匹配根因库。
- **强制规则：根因不得重复其所属风险已有的内容**。不得复述风险描述中的句子或数字（目标、进度、预测、缺口、超期条数与金额等），也不得以风险名称作为根因名称；根因只写原因及支撑它的其他指标事实。程序校验：根因名称与风险名称重复、包含风险描述中 8 字以上的原句、或引用风险描述中 3 个以上的数字时，带原因重试一次，仍不合格的根因丢弃。
- 根因中的数字必须来自输入（BR-D02，12 以内的整数除外）。
- 根因默认展开，标注“（AI 分析 · 待核实）”。
