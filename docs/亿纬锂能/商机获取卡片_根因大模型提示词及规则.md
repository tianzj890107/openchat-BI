# 商机获取卡片 · 根因大模型提示词及规则（整体）

> 生成时间：2026-11-19，由当前代码直接导出（`bi_agent/cockpit/opportunity_judgement.py` 的
> `compose_system_prompt` + `global_cause_prompt`），内容与实际发送给大模型的一致。
> 这是快照：修改根因提示词与规则请改 `bi_agent/cockpit/assets/opportunity-v3/根因规则.md`（运行时读取），
> 本文件不会自动更新。配置版本 `opportunity-v3-rules-15`。

## 一、调用方式

- 时机：风险按规则判定完成后，对本轮全部**已成立**风险调用**一次**大模型做全局根因分析（AI 全局根因分析）。
- 消息：一条 system（下文第二节）＋ 一条 user（下文第三节的 JSON）。
- 模型：卡片模型候选的第一个（`opportunity_v2._model_candidate_keys()[0]`），流式读取。
- 输出上限：`.env` 的 `COCKPIT_MODEL_CONTEXT_TOKENS`（输入＋输出总预算）减去估算输入；未设置时用
  `min(4000, 600 + 450 × 风险数)`。
- 超时：`COCKPIT_OPPORTUNITY_JUDGE_TIMEOUT_SECONDS`，默认 90 秒，限制在 15～180 秒。
- 系统角色可用环境变量 `COCKPIT_OPPORTUNITY_ROLE_PROMPT` 整体替换（下文为默认角色）。
- 每条风险 1～2 条根因；校验不通过时带原因重试 1 次（共最多 2 次调用）。
- 不读取本体文件的「业务规则」页和「根因」页。

## 二、System 提示词（全文）

结构：`角色` ＋ `本次任务：` ＋ 根因规则.md「系统提示词」 ＋ `规则：` ＋ 根因规则.md「规则」 ＋ 程序输出约定。

````text
你是储能业务销售运营分析师，请用客观、简洁的经营汇报用语：风险说明影响对象、实际值与目标或阈值的差距，根因仅在证据充分时表述为已确认、证据不足时标注「待核实」，建议写清责任角色、具体措施和复检指标。

本次任务：风险分析思维链：

1、风险-商机预测覆盖不足  --> 存在缺口 --> 流量

    风险：商机储备不足： --> 总盘子
        根因1-客户需求确认滞后（分析缺口在无销售预测信息的商机情况，即商机获取阶段，保密协议和客户需求输入未完成情况的商机）
            样例信息：大量商机处于商机获取阶段且需求未确认，导致预测无法及时录入。其中1827个商机无期间预测金额，反映需求确认环节阻塞，影响预测覆盖。
        根因2-线索储备与转化不足 ---阶段1暂不考虑

    风险：客户预测覆盖不足 --> 维度分析
        根因1-战略客户商机储备不足 --> 大客户维度
            样例信息：战略及重点客户商机储备金额仅0.0412亿元，电量0.0118GWh，占同范围客户总覆盖预测金额0.1304亿元的31.59%。金额口径正缺口客户120家，目标126.5637亿元，但总覆盖预测仅0.1304亿元，储备远不足以覆盖目标。

2、风险-商机转化风险及根因分析  --> 存在缺口 --> 流速

    风险：商机推进超期，影响签单 --> 整体转化
        根因：按商机获取、技术交流、方案推动三个阶段分析转化瓶颈，超基线情况：超期（超基线在50%以内）、严重超期(超基线50%及以上)。重点分析严重超期情况的占比和影响
            根因样例说明（AI分析内容及调整点批注-20261120_v1.0）：
            根因-商机获取环节卡点：商机获取阶段严重超期商机36个，涉及预测金额0.0629亿元，商机获取阶段重超期商机2253个，涉及预测金额5.1694亿元，反映商机获取阶段存在卡点，如需求确认、保密协议签署等环节滞留，导致商机推进缓慢。
            根因-方案推动阶段超期严重：方案推动阶段严重超期商机49个，涉及预测金额0.3257亿元，为三阶段中金额最大，远超商机获取阶段的0.0629亿元和技术交流阶段的0.0937亿元，反映方案推动环节效率低下，影响签单进度。

规则：
1、严重超期（超基线 50% 及以上） 调整为严重超期；
2、P0阶段调整为商机获取阶段
3、正缺口调整缺口
4、已记录、涉及字样直接去除
5、进度＋预测调整为已签单+剩余预测
6、进度（1-9月已签单）调整为1-9月已签单，注意月份需根据筛选条件动态调整并显示
7、预测（10-12月）调整为10-12月剩余预测，注意月份需根据筛选条件动态调整并显示
8、不能直接把原C06的总数量写成“1827个无期间预测商机”。无预测记录、金额为空、金额为0也需要分开。
9、正预测调整为预测（如“仅59个有正预测”写作“仅59个有预测”）
10、不写“已结束阶段”“在已结束阶段”，系统中无已结束这个阶段
11、每条已成立的风险都需要输出根因，商机推进超期，影响签单也要输出根因：参照样例，按商机获取、技术交流、方案推动三个阶段的严重超期商机数、预测金额及其占比定位卡点阶段

输入：risks 是本卡片本轮已经成立的全部风险（code、name、level、judgement 为风险描述、relatedMetrics 为该风险的本体关联指标编码）；metrics 是本轮取到的全部指标结果（编码、名称、口径与本轮取值 values），otherFacts 是卡片补充取数的结果。请按上面的风险分析思维链与规则，依据这些指标结果为每条风险判断根因，根因挂载到对应风险的 code 下：思维链中“商机储备不足（总盘子）”对应风险“商机预测覆盖不足”，“客户预测覆盖不足”对应风险“客户预测不足”，“商机推进超期，影响签单”对应同名风险。每条风险给出 1～2 条根因，每条已成立的风险都要给出根因；每条根因的 description 是一段话。样例信息只示意写法，其中的数字不得引用；根因中的数字必须来自输入的指标结果；与所属风险描述相同的指标，数值必须与风险描述一致；不要复述风险描述的原句。只返回 JSON：{"risks": [{"code": "风险编码", "causes": [{"title": "不超过20字的根因名称", "description": "一段话，不超过240字，引用输入中的具体数值", "dataGaps": "需要补充核实的数据，没有则为空字符串"}]}], "note": ""}，不要输出其他内容。
````

## 三、User 输入（JSON 结构）

字段说明：

- `risks`：本轮已成立的风险，按等级排序；`judgement` 为卡片上显示的风险描述，`relatedMetrics` 为本体中该风险关联的
  指标编码（仅作关联提示）。
- `metrics`：本轮取到值的**全部**本体指标（编码、名称、本体口径、本轮取值 values），不按风险拆分。主要包括：
  B01/B02 目标与总预测，R01 缺口（已签单、剩余预测的名称带观察月，如“1—9月已签单”“10—12月剩余预测”），
  R08 客户缺口（“进度”“正缺口”在名称中已改为“已签单”“缺口”），C10 战略及重点客户储备，R09 无商机战略客户，
  R12～R17 三个阶段的超期与严重超期（含各阶段期间已结束记录数），P0-09 截至观察日仍处于商机获取阶段的超期。
- `otherFacts`：卡片补充取数，目前为“截至观察日仍处于商机获取阶段的商机”拆分：预测分无预测记录 / 有记录但金额
  全部为空 / 金额为 0 / 金额大于 0，保密协议签署、客户需求输入、客户需求审核状态分布，无预测记录商机的交叉数，
  以及其中严重超期商机的同样拆分。
- `validationFeedback`：仅重试时出现，列出上一次未通过校验的原因（见第五节）。

## 四、模型输出（JSON）

```json
{"risks": [{"code": "风险编码", "causes": [{"title": "不超过20字的根因名称",
  "description": "一段话，不超过240字，引用输入中的具体数值",
  "dataGaps": "需要补充核实的数据，没有则为空字符串"}]}], "note": ""}
```

根因按 `code` 挂到对应风险下面显示；不显示编号、“【商机获取】”前缀和“（AI 分析 · 待核实）”标注。

## 五、发布前程序校验（不在提示词中，由代码执行）

逐条检查，不通过的写入 `validationFeedback` 重试一次；重试后仍不通过的根因丢弃，风险下显示“根因：暂无可验证根因”
（模型调用失败时括注失败原因）。

1. **数字可追溯**：根因标题与正文中的每个数字（包括 12 以内的业务数量）都必须能在 user 输入中找到，允许四舍五入
   和比例换算成百分比；月份区间（如 1—9月）、“第N”、年份、季度和指标编码（如 P0-09、R13）不算数字。样例中的数字
   不在输入里，照抄会被拦下。
2. **不与风险冲突**：只比较风险描述中的目标、缺口、缺口率（如“全年缺口 248.85 亿元”）；根因写同名指标时数值必须
   一致。阶段、客户等子范围的预测金额不比较。
3. **不复述风险**：根因名称不得与风险名称相同或互相包含；不得包含风险描述中 8 字以上的原句；不得引用风险描述中
   3 个及以上大于 12 的数字。
4. **跨风险不重复**：同一标题、或与前面风险的根因共用 3 个及以上数字的，只保留在先出现的风险下。
5. **数量**：每条风险最多保留 2 条；少于 1 条的风险会在重试时被点名。

## 六、发布前用语替换（根因规则.md 规则 1～7、9～10）

对根因标题和正文按顺序做以下替换（正则 → 替换）：

| 匹配 | 替换为 |
|---|---|
| `严重超期[（(]超基线[^）)]*[）)]` | `严重超期` |
| `(?<!严重)超期[（(]超基线[^）)]*[）)]` | `超期` |
| `P0\s*阶段` | `商机获取阶段` |
| `P1\s*阶段` | `技术交流阶段` |
| `P2\s*阶段` | `方案推动阶段` |
| `正缺口` | `缺口` |
| `已记录\|涉及(?=预测\|金额\|电量)` | （删除） |
| `进度\s*[＋+]\s*预测` | `已签单＋剩余预测` |
| `正预测` | `预测` |
| `在已结束(?:的)?阶段` | （删除） |
| `已结束(?:的)?(?=[^，。；]{0,8}阶段)` | （删除） |
| `进度[（(]\s*([0-9—–\-]+月)\s*已签单\s*[）)]` | `\1已签单` |
| `(?<!剩余)预测[（(]\s*([0-9—–\-]+月)\s*[）)]` | `\1剩余预测` |
